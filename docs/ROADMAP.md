## 当前安装入口（2026-10-05）

应用层内存重构/优化现统一为 `BepInEx/plugins/VaMMemory/VaM.Memory.dll`；六旧 DLL 和 UI 的内存安装/泵/卸钩入口已迁出。UI 4.6.302通过可选桥接提供场景窗口与输入，不拥有内存服务；移走统一 DLL 后下一次启动不恢复旧入口，往后内存更新只覆盖统一 DLL。原 GC/运行库/画质保持，配置在 `BepInEx/config/vam.memory.cfg` 继承原值；工具资源自动解到 cache。交付和定向回归边界见 `memory_unified_20261005/README.md`，本次不新增实机水位收益结论。

## 用户更新的长期目标（2026-10-05）

基于外部 AI 规划，逐步重构 VaM 内存管理，使反复加载人物与复杂场景时的**驻留物理内存水位增长收敛**。引用计数修复是机制证据，不是最终验收。

复杂难点可交由用户求助外部 AI：本地执行者应先整理源码、有效执行体/补丁身份、最小复现、测试边界、实际输出和明确问题，打包并附可复用提示词。可以自行闭合的问题继续本地执行，不为每个小问题请求外援。

## 最终实测口径

- 固定人物、包版本、画质、必要插件和复杂场景顺序；如 LDR→Westo→LDR。先约定首次使用轮次、总轮次及后续斜率判定，不事后选择稳定区间。
- T0 和每次相同外观返回的**首次统一 Ready**为原始端点；另记 drain 完成点，不替换首次 Ready 数值。
- 同时记录总 Working Set、可区分的 private resident、Private commit、GC allocated extent/whole-free committed、资源必要/池化/退休/未知成本和计数。
- 记录加载峰值、首次可用画面时间、完整 Ready 时间、长帧；保留必要纹理、网格、形变、锁、复用身份和插件行为。
- 以同一稳定场景的预先测得波动作为参照，评估后续返回驻留水位的斜率与区间；同时解释 Private/GC/native 分账。单次 GC 后下降、计数漂亮或 helper 少占内存都不代替多轮收敛。
- 采样优先读取驻留状态，再做可能触发缺页的深内容读取；跨 epoch、GC 阶段或身份不一致的细分归因保留未知。

实际场景切换、VR 冒烟和测试输入由用户配合；不自动重启游戏、换衣或加载场景。现有 Presence、ScenePreloadLease、CUA、target/包租约、纹理/磁盘缓存与 GC 策略继续保留，单变量逐步验证。
